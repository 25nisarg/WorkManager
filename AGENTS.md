# Freelance Manager - Codex Project Instructions

## 1. Project Purpose

Freelance Manager is a secure web application for managing freelance academic/technical work.

The application tracks:

- Work received from students
- Work received from vendors
- Work received from other freelancers
- Work completed by the owner
- Work outsourced to writers/freelancers
- Client payments
- Writer payments
- Outstanding client balances
- Outstanding writer balances
- Assignment-specific expenses
- General business expenses
- Deadlines
- Revenue
- Profit
- Cash flow
- Reports

The application is initially used by one owner, but the architecture must remain multi-user ready.

Each user's data must remain completely isolated.

## 5. Security Requirements

Security is critical.

Every business record belongs to an authenticated user through owner_id.

Never trust owner_id supplied by the browser.

Where possible, derive ownership using the authenticated Supabase user.

Never expose:

- Supabase service_role key
- Supabase secret key
- database credentials

Never disable RLS to solve an application bug.

Never expose financial or client records publicly.

All protected pages must verify authentication.

The application should remain safe for future multi-user use.

Do not assume one assignment has only one writer.

An assignment may have:

Writer A -> Report
Writer B -> Coding
Writer C -> Presentation

Use assignment_workers.

- worker_id

- status

---

## 14. Client Payments

Do not store only "advance" and "remaining".

A client may pay multiple times.

Each client payment is an individual transaction.

The application should calculate:

Total received

and

Remaining balance

from transactions.

---

## 15. Foreign Currency

Client payments may originate in another currency.

Example:

Student pays AUD 150.

Store both:

Original amount: 150
Original currency: AUD
Actual INR received: 8450

Financial reporting should use the actual INR amount received when appropriate.

Do not automatically overwrite historical conversion values using current exchange rates.

---

## 16. Writer Payments

Writers may also receive multiple partial payments.

Writer balance:

agreed writer cost - total writer payments

Do not manually store writer balance if it can be calculated.

---

---

## 18. Financial Definitions

Use these concepts consistently.

Total Work Value:
Sum of assignment selling prices.

Client Received:
Sum of client payments.

Client Outstanding:
Selling price - client payments.

Writer Cost:
Sum of agreed writer costs.

Writer Paid:
Sum of writer payments.

Writer Payable:
Writer cost - writer payments.

Expected Gross Profit:
Selling price - writer cost.

Expected Net Profit:
Selling price - writer cost - assignment expenses.

Current Cash Flow:
client payments received - writer payments made - expenses paid.

Do not confuse expected profit with current cash flow.
